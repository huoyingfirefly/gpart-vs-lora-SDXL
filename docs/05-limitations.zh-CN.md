# 局限

汇总版。每一条都说明「没做什么」，以及如果忽略它，哪个结论就会变成越界。

## 1. 范围

| | 测了 | 没测 |
|---|---|---|
| 底座模型 | NoobAI-XL v1.1 (SDXL) | 任何 SD1.5 / SD3 / Flux 模型 |
| 任务 | 1 个角色、1 个画风、这两者的 1 次加法叠加 | 组合（多角色）、概念学习、姿态、光照、control |
| 角色 | `aima`；`juxueli` 以单臂形式进行中 | — |
| encoder | 只用 UNet | text encoder（内置的 GPart 路径训不了它） |
| 分辨率 | 832×1216，buckets ≤1536 | 高分辨率、tiling |

一个角色加一个画风，足够证伪「GPart 的优势来自它的参数化」—— 因为那是一个全称
命题，一个反例就能推翻。但它**不**足以确立「LoRA 普遍更好」—— 那同样是一个我们
没测过的全称命题。

## 2. 没有扫描的超参

| 旋钮 | 测过的点 | 缺口 |
|---|---|---|
| GPart `d` | 23.2 M、50 M | 两个点、一个角色；与 lr 的交互没测 |
| GPart lr | 只有 5e-4 | 整条 headline 就是关于 lr 的，而我们从未改过 GPart 的 lr |
| GPart target modules | attn2、all-linear、只有 `ff` | 两者之间的部分覆盖，例如 attn+ff 但不带 conv |
| LoRA rank | r8、r16 | r4、r32、r64 |
| LoRA α/rank 比 | 0.5 | 被两套配方固定死了 |
| caption 扩展 | 3 个变体 | 变体配比没有做消融 |
| α（强度） | 见 `01-protocol.zh-CN.md` §5 | GPart attn2 在 1.0 以上没扫；attn2 与 all-linear 的 α 对比是跨不同 run 的 |

**lr** 那一行是最重要的。我们判定开箱结果是 lr 造成的假象，并通过把 *LoRA* 挪到
GPart 的 lr 来证明它。我们从未把 GPart 挪到别的 lr。所以严格地说：「在 lr 5e-4、
其他全部对齐的条件下，LoRA 赢」。一个在 1e-3 下表现更好的 GPart run，并没有被排除。

**画风侧的覆盖率 vs 训练预算。** 全参版画风（`style_alllinear_2026-10-30/r1999_d23m`）
只训了 600 步，attn2 版画风是 1200 步。`03-results-style-stacking.zh-CN.md` §5 的等
‖ΔW‖ 对照对齐了位移，但没有对齐每个模块学到的量，所以「扩大覆盖率对画风叠加更差」
是关于那个 adapter 的陈述，不是对覆盖率的干净消融。没有 1200 步的全参版画风可用。

## 3. 指标局限

- **tag 分数不是图像质量。** α 扫描把这点具体化了：分数升到 0.57，同时饱和度、
  边缘能量和构图都在退化。本仓库里每一个分数都该和对应的 `dRGB`/`S`/`edge` 行、
  以及图像放在一起读。
- **没有感知 / 特征空间指标。** 没有 CLIP、DINO 或 LPIPS 距离，没有人偏好研究。
  图像统计量只是廉价的代理。
- **两个画风指标互相矛盾，而且分歧量和效应量同阶。** `|z|`（整图色彩）和 `SWD`
  （patch 级纹理）对同一批臂给出不同排名 —— 见 `03-results-style-stacking.zh-CN.md`
  §5。两个都不是真值，所以只靠其中一个立起来的结论，是关于那个指标的结论。
- **画风指标对取景敏感。** 裁掉 65% 的画面能把 `|z|` 移动 0.8–2.4，比多数臂之间的
  差距还大。内容闸门（WD14 `1girl` ≥ 0.5）能挡掉最糟的失败 —— 空画面被读成完美
  匹配 —— 但挡不掉取景敏感性。
- **身份指标取决于 prompt，而且依赖很大。** 换 prompt 集会移动 0.22，叠一个画风
  adapter 再移动 0.09（`02-results-character.zh-CN.md` §5）。它测的是某个配置，
  不是某种方法。
- **阈值敏感性。** tag 命中用 p ≥ 0.35，没有做敏感性分析。换一个阈值会移动每一个
  绝对数字；base 那一行锚定着比较。
- **tag 集合是量身定的。** 每个角色 10 个 tag，事后按 caption 词频挑选，并按 base
  区分度过滤。这是一个合理的流程，但不是预注册的。
- **图像是被看过的。** 那些定性观察（α 1.5 的偏色、1.8 的背景糊）在统计量之外
  没有被量化。它们作为观察陈述，不是作为测量。

## 4. 实现局限

- **4.2× 的训练成本是本仓库 `stateless` backend 的。** 见 `04-cost-model.zh-CN.md`。
  一个实体化 `P` 的实现会更快，也更吃内存；我们在 8 GB 里跑不动它。
- **没有训练 text encoder。** kohya 里的 LoRA 可以训 TE；这里内置的 GPart 路径
  不能。这是一个有利于 LoRA 的不对称，而我们没有消除它 —— 不过要注意，这些 run
  里 LoRA 也没训 TE（`train_unet_only`），所以比较本身是对称的。
- **组合只测了加法。** 那个驱动 GPart 的结构性主张 —— 在共享坐标下、在非线性
  合并运算下保持精确的线性组合 —— 没有实现。对任何想按 GPart 自己的标准来评估它
  的人，这是最大的未测缺口。
- **α 扫描只在 `p0` 上打分**，`n = 6`，单个角色。
- **`p2`（留出的 caption）只有三行。**

## 5. 统计

- 角色行：`n = 6` 个 seed，但只有一个角色。seed 方差测了；跨角色方差没测
  （`juxueli` 待定）。
- 画风与 stacking：`n = 3` 个 seed × 2 个 prompt = 每格 6 张图。样本很小。
- 步数曲线在 400/600/800 用 `n = 3`；这三个点之间的差异在噪声范围内，不读成
  一条曲线（只有 800 与 400 之间的配饰差距是稳健的，而且很大）。
- **四景别留出集每臂 12 张**（4 prompt × 3 seed）。按这些格子做配对 bootstrap，
  0.05–0.13 的身份差距 95% 区间跨 0，0.13 那个刚刚跨出界。这个 `n` 下不要
  把 0.05 的臂间差当作结果。
- **置信区间只在算过的地方报告** —— 即 `02-results-character.zh-CN.md` §5 的身份对比。
  只来自 `p0` 的表（`n = 6`）没有区间；把 ±0.05 当作噪声，不要过度解读 0.55 vs 0.57。
- **画风指标没有为每臂加样本量。** 12 张图做 patch 云的 Wasserstein 距离是偏薄的；
  相邻臂之间的 `SWD` 排序在它自己的抽样噪声之内。

## 6. 可复现性

- 确切的底座 checkpoint（NoobAI-XL v1.1）没有在这里分发。数字依赖它。
- 训练用了特定的 latent 缓存；用不同的 VAE build 重新编码原图，可能让结果轻微偏移。
- sampler 必须用 `trailing` spacing。`leading`（很多 scheduler 在 diffusers 里的
  默认值）在相同设置下会产出肉眼可见不同的图像，且不会复现这些数字。
- **超过 77 个 CLIP token 的 prompt 必须分块编码，不能截断。** 在修好之前，
  `src/sample.py` 用 `truncation=True`，悄悄丢掉了第 77 个 token 之后的一切；
  ComfyUI 和 A1111 是连续编码多个 77-token 窗口再拼起来。修好之前产出的、用了
  详细 prompt 的任何数字，都是短于屏幕上那个 prompt 的数字。现在 `src/sample.py`
  里的分块路径对本来就在一个窗口内的 prompt 给出相同 embedding，所以短 prompt
  的数字不受影响。
- 社区 kohya 画风 LoRA（`reserve1999_style_v3`，rank 32）是外部下载，不在这里分发。
  它的 `‖ΔW‖` 和模块清单记在 `results/tables/holdout_three_family.csv`；除了它自带的
  元数据之外，无法把它的身份钉到某次具体训练。

## 7. 一个公正的审稿人会怎么说

> 你测了一个角色、一个画风、一个底座模型，只变动了配方和强度。你证明了最初报告
> 的差距经不起这个控制，这是一个有用的阴性结果。你没有证明低秩 adapter 普遍更好，
> 你也没有测 GPart 真正声称的那个组合性质。

这就是正确的读法，而 `00-claims.zh-CN.md` 正是照这个写的。
